# 轻练首位客户试用 Runbook

这份 runbook 只服务一名教练和一名低风险成年客户。它描述怎样把已验证的软件交给人工操作，不把自动化测试或网页预览写成真实微信/真机证据。

## 试用前检查

1. 由教练确认客户为成年、低风险，并在现有沟通渠道中同意参与七天试用。
2. 在服务端 secret store 配置微信登录和数据加密所需的 secret；secret 不进入小程序包、issue、日志或截图。
3. 配置一个独立的客户 API origin。不要把教练私有 Sites 地址填入小程序。
4. 应用 D1 migrations，确认运行态可以写入、恢复，并完成一次恢复演练。
5. 运行 `node scripts/pilot-preflight.mjs`。它只检查源码表面和配置边界，不显示任何 secret。

## 沙盒路径

在测试微信应用和 DevTools 中，以一条新邀请完整走一遍：

1. 教练创建一次性邀请。
2. 客户接受邀请并完成微信登录。
3. 客户分别同意健康资料、自动化/第三方处理和（可选）提醒说明。
4. 客户提交目标、身体指标、训练经验、训练条件、伤病、过敏和饮食偏好。
5. 教练查看风险标记并确认资料；高风险资料停止在人工处理状态。
6. 教练明确触发本机 Codex CLI，导入通过校验的草案。
7. 教练逐日检查动作、餐次、份量、kcal、提醒和安全说明，确认并发布。
8. 客户读取今天页和 30 天日历，展开动作要领，检查每项食物 kcal。
9. 客户完成一次训练/餐次/饮水打卡，并提交一次身体反馈。
10. 用疼痛为“有”的反馈验证停止提示和教练告警，再由教练确认告警。

沙盒路径只证明测试环境行为；它不证明真实客户已经使用或微信平台已经审核通过。

## 停止、回滚和删除

- 客户出现疼痛、身份/计划归属不清、同意撤回或发现计划异常时，立即停止相关动作和试用，通知教练人工处理。
- 需要调整时只创建未来生效的计划版本，不覆盖历史计划日和打卡。
- 客户申请删除后记录恢复期状态；恢复期结束后执行身份、健康资料、草案、反馈、告警和 session 清理。
- 任何无法确认的微信身份、设备观察、数据恢复或平台审核结果，都记录为 blocked/partial，不宣称正式上线。

## 证据边界

- 自动化测试：证明页面服务/API 的外部行为和安全失败路径。
- DevTools/模拟器：证明测试包能够编译和运行部分路径。
- 真实设备：证明指定设备、指定账号、指定版本上的实际像素与交互观察。
- 七天试用：证明一名具体客户的执行结果，不外推为普遍留存或生产就绪。

每类证据分别保存版本别名、时间、环境别名和脱敏引用；不要把 token、OpenID、AppSecret、完整客户资料或私有 URL 写入记录。
