# 生成由教练本机 Codex CLI 触发

**Status: superseded (2026-09-14) — 见下方修订**

计划草案只在教练明确触发后，由教练本机的 Codex CLI 生成；服务端负责受控交接和确定性校验，教练仍必须审核并发布。这个边界保留了健康资料和生成凭证的最小暴露面，也避免把自动化生成误认为已批准内容。

## 修订：试点期由操作员运行生成（accepted, 2026-09-14）

让健身教练安装并运行 Codex CLI 门槛过高。首客试点期间，生成由操作员（Wendy，在 Park 的 Mac mini 上）为每位客户运行一次：从云函数取出去标识化档案 → 本机 Codex CLI 生成 → `plan.v1` 校验 → 以草案导入。教练只负责确认资料、审阅草案和发布。

不变的部分：生成仍是显式人工动作，不由服务端自动调用模型；草案未经教练确认不进入客户端；原始 prompt/completion 不落库。第二位客户或第二位教练之前，需要以独立运行时合同建设可信生成网关，届时再修订本 ADR。
